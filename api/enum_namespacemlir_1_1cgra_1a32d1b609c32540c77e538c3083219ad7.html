Enum FabricOpSupport

  • Defined in File CGRAAnalysisUtils.h

Enum Documentation

enum class mlir::cgra::FabricOpSupport

How an op inside a candidate loop relates to the STRELA fabric’s supported operation set (the mapper’s pe_features.py OP_REQUIRED_FEATURES: add/sub→A, mul→M, shl/shr→S, and/or/xor→L, cmp→A,C, select→P).

The CGRA legalization passes (--legalize-to-i32, --affine-to-cgra, --normalize-cgra-compare, --predicated-store-to-select, --expand-fabric-ops) lower i8/i64 arith, max/min, ext/trunc, unsupported compares, power-of-two divide/remainder and the integer math intrinsics to fabric-native ops. They are WHOLE-MODULE passes (not scoped to cgra.deploy) and in the shipped pipelines run BEFORE annotation, so those ops are typically already lowered here; this classification is order-independent and treats them as Ok regardless, rejecting only ops NO transform can ever lower.

Values:

enumerator Ok

A fabric FU op, an op a CGRA transform lowers to one, or loop/ conditional/memory control — offloadable (possibly only after legalization).

enumerator Unlowerable

No CGRA transform can ever turn it into a fabric op (floating point, a divide by a non-power-of-two, a floating-point math intrinsic, a call) — the loop can never run on the fabric.

enumerator Unknown

Unrecognised — likely not mappable, but not provably so.
