Function mlir::cgra::hasBackpressureCycle

  • Defined in File CGRAAnalysisUtils.h

Function Documentation

inline bool mlir::cgra::hasBackpressureCycle(mlir::affine::AffineForOp loop, unsigned bufferDepth = 2)

Whether the loop nest containing loop is fabric-streamable.

A compute nest maps to a single 1-D STRELA config only when it has constant loop bounds AND no reduction — every loop induction variable must index some affine.store (the nest’s output). A reduction IV appears in a load but not the output (a conv’s window, a dot-product accumulation) and needs fabric accumulation the 1-D stream model cannot express, so such a nest runs on the CPU. --generate-cgra-driver (fabric config vs CPU) and --export-loop-dfg (which innermost loops to emit) SHARE this predicate so their per-nest indices line up; either may pass any loop of the nest — the outermost root is resolved here.

Does loop contain an arith op the fabric ALU can execute?

THE single definition of “this nest is fabric work”. --annotate-to-cgra uses it to decide what to wrap in a cgra.deploy, and --export-loop-dfg uses it to decide what gets a .dot. Those two decisions must be the same decision: the driver numbers its configurations from the deploys and the mapper numbers its bitstreams from the .dot files, so if the predicates ever disagree every configuration after the first disagreement is dispatched against the WRONG bitstream — silently. They used to be two independent copies, and they had drifted: lenet produced 60 deploys and 58 .dot files, numbered contiguously, so 58 bitstreams were paired with 60 configurations.

Can backpressure in loop's dataflow close into a CYCLE?

A configuration deadlocks when a fork stalls waiting on a consumer whose other operand is produced by a chain that the SAME fork feeds — directly or through another fork. fork_sender is a lazy fork (ready_in_o is the AND of its consumers) and each link holds only 2 tokens (elastic_buffer.sv), so once the skew at a join exceeds that, the short side backs up, the fork stops, and the chain the join is waiting for starves. With two such forks feeding each other’s joins the wait becomes circular and the configuration never raises exec_done.

Handshaking alone does NOT prevent this: it absorbs skew only while few enough tokens are in flight, which is why the same bitstream runs at a short dispatch length and wedges at a long one (lenet cfgs 3 and 33 are byte-identical in both DFG and mapping; 3 issues 784 dispatches of 6 elements and runs, 33 issues one of 120 and hangs).

The model: for every op taking two values produced inside the nest, if their depths from the nest’s loads differ by at least the buffer depth, record “the short operand’s source waits on the long operand’s root”. A cycle in that relation is a potential deadlock. A single chain with no cross-coupling yields no cycle, which matches the observation that those configurations never hang.

Parameters:

loop – Any affine.for of the nest.

Returns:

True if the nest is a single-config 1-D stream, false if it is a reduction/conv (CPU) or has non-constant bounds.
